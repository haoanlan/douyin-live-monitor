## 二、性能

### 接口实测（本机，gzip 后大小）

```
/api/overview                 首次 422ms  再次 6ms     10KB   ← 5 分钟进程内缓存
/api/rooms                        3ms      3ms      4KB
/api/sessions?size=20             6ms      6ms    144KB
/api/gift-prices                  8ms      7ms    311KB   ← 60s/10min 缓存 + 启动预热
/api/sessions/303/detail         11ms      8ms    189KB
/api/sessions/330/detail          4ms      5ms     75KB
/api/notify/*                   1-2ms     1-2ms
/api/upstage/status             2ms       0ms
/api/service/status               14ms     13ms     16KB
```

结论：**没有"秒级以上"的接口**。最重的两个（gift-prices / overview）都有缓存。

### 前端构建

```
JS  112 个文件，合计 3.43 MB（未压缩）
  index-*.js  1.44 MB  ← echarts + element-plus + axios + pinia + lodash 都在入口 chunk
  index-*.js  764 KB
CSS 最大 147 KB
```

- `echarts` 已是按需引入（`plugins/echarts.ts` 只注册用到的图表）
- 静态资源服务（`web-dashboard.js`）：**>1KB 的 js/css/json/html 会 gzip**；
  带 hash 的资源长期缓存，`index.html` 是 `no-store` —— 这部分没有优化空间

### 数据库

- `gifts(gift_name)` 索引已建（迁移里 `CREATE INDEX IF NOT EXISTS`），礼物价格聚合从全表扫变覆盖索引
- `gift-prices` 缓存失效点已覆盖 4 个写操作（改价 / 恢复 / 重算 / 同步单价）

### 前端定时器

审计了 26 个含定时器/监听的文件：Vue 组件（场次详情、总览）都有 `onUnmounted` 清理；
`socket/index.ts` 的 `close()` 会 `clearAllTimers()`。
**唯一小瑕疵**：`gift-prices` 页的预览 300ms 防抖定时器没有在离开页面时清（最多多打一次接口），可忽略。

## 三、逻辑

### 已修

1. **越权入口**：`POST /api/report/generate` 没有权限校验（任何登录用户都能触发一次无头浏览器渲染）。
   由于它同时是死接口，**直接删除**，比补权限更干净。
2. **总览数据不及时**：`/api/overview` 有 5 分钟缓存，但只有「补录礼物」会清它。
   现在新增 `lib/cache-bust.js`，并在以下写操作后调用：
   - 礼物价格：改价 / 恢复默认价 / 重算历史 / 同步单价（4 处）
   - 删除场次

### 核对过没问题的

| 点 | 结论 |
| --- | --- |
| 写接口鉴权 | 34 个写接口全部有校验（`requireAction` / 顶部统一 `requireAction` / 自己的令牌）。唯一漏的 report/generate 已删 |
| 场次切换 | 场次历史页有 `watch(route.query.hostId)`，换主播会重新取数，不会显示上一个主播的数据 |

## 四、动画

### 已修：两套入场动画互相覆盖

同一张卡片被两条规则同时命中：

```css
.dy-stagger > *                    { animation: dy-rise-in 320ms ... }   /* 位移 10px + 淡入 */
.douyin-page > .art-card           { animation: dy-card-in ... }         /* 只有淡入   */
```

后加载的那条赢 → **`dy-stagger` 实际是死的**；而且非 `.art-card` 的子元素仍会做 10px 位移，
和注释里"位移一律去掉（用户明确反感内容往上顶）"自相矛盾。

处理：
- `dy-rise-in` 改成**纯透明度**（去掉 `translate3d`）
- 删除 `.douyin-page > .art-card` 那一整套（含 8 级 `nth-child` 延迟、reduce-motion 覆盖）
- 统一由 `.dy-stagger` 负责入场：30ms 步进、最多 8 个、320ms
- `prefers-reduced-motion` 下只保留 120ms 淡入（统一用 `dy-rise-in`，原来错用了给图片的 `dy-img-in`）

### 其他核对

| 项 | 状态 |
| --- | --- |
| 重复 keyframes | 已去重（`dy-spin` 原来两个定义） |
| 页面切换 | 单一 Transition + `mode="out-in"`，任何时刻只有 1 个 `.art-page-view`（上一轮 `7fcbe34`） |
| 弹窗入场 | `dialog-open/close` 只在 `el-dialog` 上，未和页面入场叠加 |
| Element 浮层 | `.dy-stagger` 显式排除 `el-overlay/el-drawer/el-dialog/el-message-box/el-loading-mask`（否则 fixed 元素会被 transform 拽住） |
| 减弱动效 | 页面切换、stagger、热力图格子都覆盖了 `prefers-reduced-motion` |
